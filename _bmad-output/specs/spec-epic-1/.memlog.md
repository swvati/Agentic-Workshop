- (direction) User requested a spec from INTENT.md with slug epic-1; distill the structured source without story breakdown.
- (capability) CAP-1: Represent each triage decision as JSON with an allowed category (billing, bug, access, performance, how-to), priority (P1-P4), corresponding route, and one-sentence rationale; reject anything else with a clear error.
- (capability) CAP-2: One command, uv run python load_seed.py, loads seed/tickets.csv and seed/customers.csv into local app.db tables tickets and customers with CSV-matching columns; rerunning leaves the same database.
- (constraint) Use Python 3.12 or newer and uv.
- (constraint) Treat both seed CSV files as read-only.
- (constraint) Make no network calls and require no API keys for this epic.
- (constraint) Preserve compatibility with mcp/triage_server.py by keeping the app.db table and column names it reads.
- (non-goal) The agent, MCP tools, evals, and user interface are out of scope.
- (direction) Adopt mcp/triage_server.py and both seed CSV files as companions so downstream implementation preserves the existing database contract and input schemas.
- (question) INTENT.md lists category and route value sets but does not define their mapping. Must each category map to one specific route, or is any listed route valid with any listed category?
